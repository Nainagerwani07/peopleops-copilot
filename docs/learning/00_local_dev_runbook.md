# Local Dev Runbook (native, no Docker)

Ports: **API 8001**, **Web 3001**. Ports 8000 and 3000 are used by another local project.
The repo root is `~/Downloads/codebasics/peopleops-copilot`.

## 1. One-time setup (already done on 2026-10-04)

```bash
# Backend
cd ~/Downloads/codebasics/peopleops-copilot/backend
cp .env.example .env                      # then edit; see "Local .env" below
uv venv --python 3.11 .venv               # same Python version as the Dockerfile
uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/alembic -c alembic.ini upgrade head   # create all tables (16 migrations)
PYTHONPATH=. .venv/bin/python scripts/seed.py  # fill tables with fake data

# Frontend
cd ../frontend
echo "NEXT_PUBLIC_API_BASE_URL=http://localhost:8001" > .env.local
npm install
```

Local `.env` differences from `.env.example`:
- a random `JWT_SECRET_KEY` (`python3 -c "import secrets;print(secrets.token_urlsafe(48))"`)
- `POLICY_UPLOAD_DIR`, `PROFILE_PHOTO_UPLOAD_DIR` and `EMPLOYEE_DOCUMENT_UPLOAD_DIR` point to `./storage/...` (the defaults point to the Docker path `/app/storage/...`)
- `CORS_ORIGINS=["http://localhost:3000","http://localhost:3001"]`

## 2. Start the servers (two terminals)

**Terminal 1: backend**
```bash
cd ~/Downloads/codebasics/peopleops-copilot/backend
source .venv/bin/activate
uvicorn app.main:app --port 8001 --reload     # --reload restarts on code changes
```

**Terminal 2: frontend**
```bash
cd ~/Downloads/codebasics/peopleops-copilot/frontend
npx next dev -p 3001
```

Open:
- App: http://localhost:3001
- API docs (Swagger, where you can try endpoints): http://localhost:8001/docs
- Health check: http://localhost:8001/api/v1/health

Logins (all with password `password123`): `admin@mock-hrms.dev`, `manager@mock-hrms.dev`, `employee@mock-hrms.dev`

## 3. Stop the servers

- In the terminal where a server is running, press **Ctrl + C**.
- If it's running somewhere you can't see (a closed terminal or background job):
  ```bash
  lsof -ti tcp:8001 | xargs -r kill    # stop the backend
  lsof -ti tcp:3001 | xargs -r kill    # stop the frontend
  ```
- Check what is using a port: `ss -ltnp | grep -E ':(8001|3001) '`

## 4. View the database

The whole database is one file: `backend/storage/hrms.db` (SQLite).

**Option A: VS Code extension (easiest).** Install **"SQLite Viewer"** (by Florian Klampfer) and click `hrms.db` in the Explorer to browse the tables.
Or install **"SQLite"** (by alexcvzz), which lets you run your own queries: Ctrl+Shift+P → "SQLite: Open Database".

**Option B: command line.**
```bash
cd ~/Downloads/codebasics/peopleops-copilot/backend
sqlite3 -readonly -header -column storage/hrms.db
```
```sql
.tables                          -- list tables
.schema employees                -- show columns of a table
SELECT id, email, role FROM employees LIMIT 5;
SELECT title, category, original_filename FROM hr_policies;
.quit
```
`-readonly` means you can't change data by accident.

**Option C: GUI app.** DB Browser for SQLite (`sudo apt install sqlitebrowser`).

## 5. Reset the database

`seed.py` **deletes** existing rows before inserting new fake data, and the names change on every run (Faker isn't given a fixed seed). To rebuild from scratch:
```bash
cd ~/Downloads/codebasics/peopleops-copilot/backend
rm -f storage/hrms.db
.venv/bin/alembic -c alembic.ini upgrade head
PYTHONPATH=. .venv/bin/python scripts/seed.py
```

## 6. Where the data comes from

All data is **fake**, generated by `backend/scripts/seed.py`:
- 3 fixed demo users (admin, manager, employee) plus 1,000 employees generated with the `faker` library
- departments, projects, skills, assignments, leave balances and payroll, all generated in loops
- bank and PAN numbers are built from formulas (not real, but still treat them as sensitive)
- **22 HR policies**: one line of text each, hardcoded in `seed.py` and written to `storage/hr-policies/seed_policy_XX.md`
